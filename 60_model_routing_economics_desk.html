Teaching note · for the instructor

60Model-Routing Economics Desk

⏱ 10–15 min live · ~20 min with debriefEconomics, ROI & measurementFramework · AI Tool Selection Quartet
Purpose

Sending every request to one model — usually the strongest — is the most expensive habit in AI operations. Students inspect six task segments and four model profiles, write routing rules that send easy work to efficient models and hard or high-value work to stronger models or people, then run a batch and read cost, latency, quality, and misrouting. Halfway through, the instructor changes the task mix to test whether static rules survive contact with a shifting workload. The aha is that a deliberate model portfolio beats one-model-for-everything, and the cost of misrouting a hard task cheaply can dwarf the savings.

Concepts to explain & how

Segment tasks before choosing a model

How: Walk the six segments and ask what signal predicts difficulty — length, ambiguity, stakes. Routing starts with reading the task, not with picking a favorite model.

Match each segment to a model on cost, quality, and latency

How: Have students write rules against the four model profiles and run the batch. Read the dashboard aloud: cheap-and-fast for easy volume, strong-and-slow for the hard tail, a person for the highest stakes.

Misrouting has an asymmetric cost

How: Point at a hard task sent to the cheap model: the failure, rework, and downstream damage cost far more than the tokens saved. A false cheap-route decision is not symmetric with a false expensive one.

Common misconceptions & where students get stuck
  • "Use the best model for everything to be safe." The batch results show the strong-model-for-all rule bleeds cost and latency on easy volume a cheap model handled fine.
  • "Route everything cheap to save money." The misrouting column shows a hard task on a weak model produces expensive failures; the cheap route has a hidden bill.
  • "A good routing rule is set once." The mid-game task-mix change breaks static rules; students see routing must track the workload, and learn when a person belongs in the route.
Facilitation & timing
  • 0:00 — Present the six task segments and four model profiles. Ask which signal best predicts task difficulty.
  • 2:00 — Students write routing rules and run a workload batch. Review the cost, latency, quality, and misrouting dashboard.
  • 6:00 — Change the task mix and re-run. Ask whether the static rules still hold; let the misroutes appear.
  • 10:00 — Open Debrief prompts: which signal best predicted difficulty, the cost of a false cheap-route decision, when a person should enter the route.
  • 13:00 — Compare team scores; Reset the workload for the next cohort.
What mastery looks like

A student who gets it can design a routing policy that segments tasks by a difficulty signal and assigns each segment a model or a person on cost, quality, and latency — and can explain why misrouting a hard task cheaply is the costly error. Takeaway: run a model portfolio, not one model for every request, and price the asymmetric cost of routing hard work to a cheap model.
